# Dotfiles

Personal dotfiles for seonjunkim, at `~/.dotfiles` (default branch `master`). They are applied in one of two ways:

- **Home Manager** (`homeModules` in `flake.nix`, modules in `nix/home/`, defaults in `nix/data/*.toml`): machines with Nix. A separate config imports the modules, pins this repo in its `flake.lock` and switches. Files come from the Nix store, so an edit here reaches a machine only after its lock is updated and Home Manager switches.
- **`setup.sh`** (engine in `bootstrap/`): machines without Nix, such as dev containers. It symlinks into `~/.dotfiles`, so edits take effect at once, and installs tools. On a Home Manager machine it leaves the files Home Manager owns alone and skips the package steps (`hm_active`, `hm_owns` in `bootstrap/lib/`).

## Platform support

This repo targets both **macOS** and **Ubuntu**. Keep all configs and scripts platform-agnostic:
- No hardcoded absolute paths (use `$HOME`, rely on `$PATH`)
- No macOS-only or Linux-only tools without guarding with `uname` checks
- `setup.sh` handles platform differences (e.g. `brew` vs `apt`) internally

## Conventions

The pre-commit hook (`.githooks/`, set as `core.hooksPath`) runs `tests/run.sh`.

Fish has two sources. Home Manager machines get `nix/home/fish.nix` with aliases and abbreviations from `nix/data/shell.toml`; setup.sh machines get `config/fish/config.fish`. A change to one usually belongs in the other too. Both use `config/fish/functions/`.

- Indent with tabs.
- Environment variables: `set -gx`, not `export`, and never universal (`set -U`).
- PATH: `fish_add_path -g`. Plain `fish_add_path` writes the universal `fish_user_paths`, which persists outside the config; `-g` changes only this shell and skips directories already in `PATH`.
- Tool-specific variables (e.g. `ANDROID_ADB_SERVER_PORT`) go inside that tool's `if command -q` block, not under `# Core Environment`.
- Named functions go in `config/fish/functions/<name>.fish`, not inline in `config.fish`.
- In functions that run on every prompt, use fish's `string replace`, not `sed`: no extra process, and the same on GNU and BSD.

## Structure

| Path | Description |
|---|---|
| `config/fish/` | Fish config and functions |
| `config/vim/`, `config/tmux/` | Vim and tmux config |
| `config/bash/` | Bash config |
| `config/claude/` | Claude Code instructions, settings, statusline, commands, agents |
| `config/agents/` | Shared agent prompt (`AGENTS.md`) and skills |
| `config/ipython/` | IPython profile |
| `config/vscode/` | VS Code settings and keybindings (Home Manager `homeModules.vscode`) |
| `config/desktop/`, `config/desktop-seed/` | i3 desktop configs, and fcitx5 settings seeded once (Home Manager `homeModules.desktop`) |
| `bin/` | Helper scripts added to shell `PATH` |
| `nix/home/` | Home Manager modules |
| `nix/data/` | Defaults read by the modules (packages, shell aliases and abbreviations, git) |
| `nix/packages/` | Pinned tools: `ccs`, `codex`, `arxiv` (each has a README on how to bump it) |
| `bootstrap/` | Modular setup engine (`bootstrap/setup.sh`, `bootstrap/lib`, `bootstrap/ops`) |
| `setup.sh` | Single bootstrap entrypoint; clones repo if needed and delegates to `bootstrap/setup.sh` |
| `tests/` | Repo checks (`tests/run.sh`) |

## Where files land

| Target | Home Manager | setup.sh |
|---|---|---|
| `~/.config/fish/` | `config.fish` generated by `nix/home/fish.nix`; `functions/` linked per file | symlink → `config/fish` |
| `~/.vimrc` | linked (`nix/home/terminal.nix`) | symlink → `config/vim/.vimrc` |
| tmux | `~/.config/tmux/tmux.conf` (`programs.tmux`) | `~/.tmux.conf` → `config/tmux/.tmux.conf` |
| `~/.ipython/profile_default` | config file linked | symlink → `config/ipython/profile_default` |
| `~/.claude/CLAUDE.md`, `statusline.py` | linked (`nix/home/agents.nix`) | symlinks → `config/claude/` |
| `~/.claude/settings.json` | managed keys merged in on each switch (`settings-merge.py`); Claude's own keys stay | copied, not symlinked (Claude Code's circular-symlink detection) |
| `~/.claude/{commands,agents,skills}/` | real directories, one link per entry | same |
| `~/.codex/AGENTS.md` | linked | symlink → `config/agents/AGENTS.md` |
| `~/.agents/skills` | linked | symlink → `config/agents/skills` |

## Skills

`config/agents/skills/` is the single source of truth for skills across all three consumers. A skill is a directory with a `SKILL.md` at its root carrying `name` and `description` frontmatter.

| Consumer | How it gets the skill |
|---|---|
| Claude Code | each top-level entry linked into `~/.claude/skills/` |
| Codex | the whole tree linked at `~/.agents/skills` |
| Claude app (web/mobile/desktop) | manual upload of a `.skill` archive built by `bin/skill-pack` |

With setup.sh the first two are live symlinks: edit a file and it takes effect. With Home Manager they follow the next switch. **The app does neither.** An uploaded `.skill` is a snapshot; the app's copy stops tracking the source the moment it lands.

To update the app after changing a skill:

```sh
skill-pack session-export        # writes ~/Downloads/session-export.skill
```

Then in the app: Settings → Capabilities → Skills → delete the old entry → upload the new archive. `skill-pack` with no arguments packs every skill; `-l` lists them, `-o DIR` changes the output directory.

Write skills to work in both environments rather than forking per consumer — branch inside `SKILL.md` on what differs (filesystem paths, available tools) so one file serves all three.

Current skills: `meeting-deck/`, `paper-review/`, `session-export/`.

## Bootstrap order (setup.sh)

1. Run `setup.sh` via `sudo bash` (once, on a fresh machine, to grant passwordless sudo)
2. Run `setup.sh` as the target user

## MCP servers

`setup.sh` registers MCP servers on every machine, Home Manager included. For Claude Code it writes `~/.claude.json` and each CCS instance's `.claude.json` (`register_claude_mcp`, idempotent). For Codex it uses `codex mcp add` instead of a repo-managed `~/.codex/config.toml`, so host-specific Codex settings (for example `projects.*.trust_level`) are not clobbered. There is no GitHub MCP server (dropped 2026-10-22: unused, agents call `gh` directly).

| Server | Command | Installed by |
|---|---|---|
| `arxiv` | `~/.local/bin/arxiv-mcp-server` (not `uvx`, which would prefer an older `uv tool install` copy) | `nix/home/uv-locked.py` from the lock in `nix/packages/arxiv/`: Home Manager through `nix/home/uv.nix`, setup.sh through `install_shared_mcp_servers` |
| `sequential-thinking` | `npx -y @modelcontextprotocol/server-sequential-thinking` | fetched by `npx` on first use |
