# Figures

## One message per figure

- Write the figure's one-sentence message first and cut every mark or label that does not serve
  it. n, percentiles, footnotes and run conditions go to the notes or a one-line caption.
- Label series directly; no stat boxes.
- Diagrams in system-figure style: layers, thin lines, few words; not boxes of numbered sentences.
- Do not chart a result the audience already assumes.

## Show the spread

- A point that summarises several measurements carries its uncertainty: an interval, a band, or
  the samples themselves (prefer the samples when they are few).
- A pooled series says what was pooled and its n. A number from one run says "one run" on the
  figure.
- On slides, show the spread quietly (a range in a cell, a thin whisker).

## Agree the spec before building

- For a paper figure, give the owner x, y, series, spread and data source per figure and wait for
  approval.
- Prefer a standard, citable analysis and name it; mark any home-made construction as such.

## Who draws

- When the owner builds the deck in their own style, deliver the message, the format and a
  script-generated data table (with a CSV) instead of a drawn figure, at an absolute path.
- When you build the deck artifact, draw simple figures in the slide itself from script-generated
  numbers, with the source and conditions in a one-line caption.

## Timelines

- Explain the mechanism in prose before drawing it.
- One operation keeps one color and pattern across rows and panels; no index-like labels; when the
  "after" splits work into pieces, draw the "before" with the same pieces; draw dependencies as
  arrows.

## In chat

Images and Mermaid do not render in the owner's chat client: write figures to files, link them,
and carry the key numbers as a table in the reply.
